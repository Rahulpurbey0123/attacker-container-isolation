## Component Responsibilities

### 1. Root Configuration & Build Files
* **[`Dockerfile`](file:///c:/Users/rahul/secure-attacker/Dockerfile)**: Defines the base environment (`ubuntu:24.04`), installs approved utilities (`curl`, `iputils-ping`), creates the non-root `student` user (UID `1001`), and prepares `/home/student/work`.
* **[`.gitignore`](file:///c:/Users/rahul/secure-attacker/.gitignore)**: Prevents accidental commit of dependencies (`node_modules`), temporary files, and IDE configs while preserving audit logs and verification reports.

### 2. Orchestration Layer (`orchestrator/`)
* **[`orchestrator/index.js`](file:///c:/Users/rahul/secure-attacker/orchestrator/index.js)**: Central orchestrator managing:
  * Express HTTP server on port `3000`.
  * Static file serving for the SOC dashboard at `/dashboard-ui/`.
  * Dynamic creation and deletion of isolated internal Docker bridge networks and containers via Dockerode.
  * Command execution gateway enforcing regex allowlists and command/chaining blocks.
  * REST API endpoints for telemetry, reporting, and container health.
* **[`orchestrator/logger.js`](file:///c:/Users/rahul/secure-attacker/orchestrator/logger.js)**: Formats and appends structured JSON entries with generated UUID event IDs and ISO timestamps to `audit.log` and `security-events.log`.
* **[`orchestrator/security-monitor.js`](file:///c:/Users/rahul/secure-attacker/orchestrator/security-monitor.js)**: Background monitoring utility that periodically polls active attacker containers to inspect command histories for package management patterns.

### 3. Security Configuration (`orchestrator/security/`)
* **[`orchestrator/security/seccomp-profile.json`](file:///c:/Users/rahul/secure-attacker/orchestrator/security/seccomp-profile.json)**: Custom Seccomp profile configured with `defaultAction: "SCMP_ACT_ALLOW"` and an explicit blocklist of dangerous syscalls (`mount`, `pivot_root`, `reboot`, `init_module`, `ptrace`, `setns`, `unshare`, etc.) returning `SCMP_ACT_ERRNO`.

### 4. Automated Verification Harness (`orchestrator/security-tests/`)
* **[`orchestrator/security-tests/verify-security.js`](file:///c:/Users/rahul/secure-attacker/orchestrator/security-tests/verify-security.js)**: Automated test harness verifying:
  1. Non-root user execution (`1001:1001`).
  2. Read-only root filesystem (`ReadonlyRootfs: true`).
  3. Dropped capabilities (`CapDrop: ALL`).
  4. Minimal capability retention (`CapAdd: NET_RAW`).
  5. Package management restriction (`apt-get update` blocked).
  6. Permitted communication to assigned target.
  7. Cross-session target network isolation.
  8. Attachment of the custom Seccomp profile.

### 5. Frontend Dashboard (`orchestrator/dashboard/` and `dashboard/`)
* **`index.html`**: Semantic layout presenting SOC telemetry, security controls enforcement, live session list, recent event table, and the Student Session Management panel.
* **`style.css`**: Professional dark cyber SOC styling with responsive cards and status indicators.
* **`dashboard.js`**: Asynchronously calls `POST /sessions` to create sessions, provides one-click terminal command copying, and polls `/dashboard` and `/security-summary` every 5 seconds.
